# Техническая спецификация проекта AnimaticAI

В данном документе приведено детальное техническое описание архитектуры, используемого стека технологий, структуры директорий, статуса реализации модулей и инструкций по запуску веб-платформы **AnimaticAI**.

---

## 1. НАЗВАНИЕ И СУТЬ ПРОЕКТА

**AnimaticAI** — это высокотехнологичная веб-платформа, предназначенная для генерации 3D-моделей на основе изображений (и текста) с помощью алгоритмов искусственного интеллекта и последующего автоматического риггинга. 

Платформа представляет собой экосистему для 3D-художников, разработчиков игр и VR/AR проектов, объединяющую:
*   Инструменты быстрого прототипирования трехмерных объектов с использованием современных диффузионных моделей.
*   Систему автоматического скелетного риггинга (Auto-Rigging) на базе интеграции с Adobe Mixamo.
*   Каталог сгенерированных и загруженных пользователями 3D-моделей с возможностью интерактивного 3D-просмотра непосредственно в браузере.
*   Социальные функции (лайки, добавление в избранное, подписки на авторов, древовидные ветки комментариев).
*   Систему монетизации (продажа кредитов для генерации и подписки Pro/Studio).
*   Панель администратора для глубокой модерации контента, пользователей, обработки жалоб и анализа финансово-операционной статистики.

## 2. ТЕКУЩИЙ СТЭК ТЕХНОЛОГИЙ

### Клиентская часть (Frontend)
*   **Базовый стек:** React 19, TypeScript (Strict Mode), Vite (сборщик).
*   **Стилизация:** Tailwind CSS v4, Vanilla CSS (пользовательские темы, глобальные стили, стеклянный интерфейс Glassmorphism).
*   **Анимации:** Framer Motion (плавные переходы страниц, hover/tap эффекты, анимация списков).
*   **3D-графика:** Three.js, React Three Fiber (R3F), `@react-three/drei` (интерактивный просмотрщик моделей GLB/GLTF, вращение, освещение).
*   **Управление состоянием:** Zustand (глобальный стейт авторизации и настроек), React Context API (контекст процесса генерации `GenerationContext`).
*   **Валидация и формы:** React Hook Form + Zod (схемы валидации).
*   **Роутинг:** React Router DOM v7.
*   **UI Примитивы:** Radix UI (доступные компоненты: Dialog, DropdownMenu, Tooltip).
*   **Компоненты аналитики:** Recharts (отрисовка интерактивных графиков прибыли, регистраций и генераций в панели администратора).
*   **Дополнительно:** `react-easy-crop` (обрезка загружаемых референсов и аватарок), `react-hot-toast` (всплывающие уведомления), `lucide-react` (библиотека иконок).

### Серверная часть (Backend)
*   **Язык программирования:** Python 3.10+.
*   **Веб-фреймворк:** FastAPI (асинхронная обработка запросов, автогенерация документации Swagger/OpenAPI).
*   **Сервер приложений:** Uvicorn.
*   **Очередь задач:** Redis + ARQ (асинхронное выполнение генераций на GPU, лимит в один поток `max_jobs = 1` для предотвращения перегрузки видеопамяти CUDA).
*   **База данных:** PostgreSQL (под управлением облачной платформы Supabase).
*   **Работа с БД:** Прямое подключение к PostgreSQL через `psycopg2-binary` (для транзакционных операций, обхода ограничений кэширования PostgREST) и официальный Supabase Python SDK.
*   **Аутентификация и безопасность:** Supabase Auth (проверка JWT-токенов доступа на бэкенде), `slowapi` (лимитирование частоты запросов / Rate Limiting), `PyJWT`, `httpx`.
*   **Интеграция оплаты:** ЮKassa SDK (`yookassa`).
*   **Почтовый клиент:** SMTP (отправка писем через Yandex SMTP SSL для подтверждения оплат, предупреждений об истечении подписок и обратной связи).

### Инструменты ИИ и Машинного обучения (ML)
*   **Tencent Hunyuan3D-1:** Интегрирован через вызов CLI-скрипта в обособленном виртуальном окружении с CUDA.
*   **Tencent Hunyuan3D-2:** Интегрирован непосредственно в ARQ-воркер (ShapeGen и PaintGen конвейеры на базе PyTorch).
*   **TRELLIS2 (Microsoft/Stable Projectorz):** Интегрирован через вызов CLI-скрипта в выделенном окружении.
*   **Обработка изображений:** `rembg` (удаление фона с использованием сессии `u2net`/`birefnet`), OpenCV (`opencv-python-headless`), Pillow (PIL), Trimesh (загрузка и базовая обработка мешей), PyMeshLab, `xatlas` (развертка текстур).
*   **Валидация референсов:** MediaPipe (`pose_landmarker_heavy.task` для проверки поз при подготовке модели к риггингу).
*   **Авто-классификация:** CLIP (автоматическое распределение сгенерированных 3D-моделей по категориям).
*   **Модерация:** Модели классификации текста на токсичность (Toxicity classifier) и изображений на NSFW (NSFW classifier).

### Инфраструктура и Деплой
*   **Контейнеризация:** Docker, Docker Compose.
*   **Production конфигурация:**
    *   **Nginx:** Используется в качестве обратного прокси, настроен на отдачу статики фронтенда, проксирование `/api` на бэкенд и `/supabase` на локальный Kong gateway. Включает оптимизацию под Range-запросы (для стриминга больших 3D-моделей GLB) и увеличенные таймауты до 900 сек.
    *   **Redis:** Кеширование и брокер очереди ARQ.
    *   **Cloudflare Tunnel:** Безопасный туннель для публикации локального/серверного окружения на публичный домен без открытия портов наружу.

## 4. ТЕКУЩИЙ СТАТУС РЕАЛИЗАЦИИ

### Выполненные модули и функции
1.  **Генерация 3D моделей:**
    *   Реализована очередь задач в Redis. GPU-воркер последовательно берет задачи, выполняет препроцессинг (удаление фона через `rembg`, центрирование, кадрирование).
    *   Поддерживаются три модели генерации: **Hunyuan3D-1** (через CLI-подпроцесс), **Hunyuan3D-2** (напрямую в коде воркера на PyTorch с поддержкой PBR текстурирования) и **TRELLIS2** (через CLI-подпроцесс).
    *   После завершения генерации автоматически создается скриншот модели (pyrender/fallback), GLB и PNG загружаются в хранилище Supabase.
    *   Модель классифицируется с помощью CLIP (для присвоения тегов категории), и сохраняется в каталог с автоматической привязкой связей.
2.  **Модерация входящего контента:**
    *   На уровне API работает NSFW-фильтр для картинок-референсов.
    *   Названия, описания моделей и комментарии проверяются на токсичность текстовым классификатором. При обнаружении нарушений запросы отклоняются с ошибкой.
    *   При генерации моделей под риггинг MediaPipe проверяет наличие человека на фото и углы сгиба рук (T-поза / А-поза). Если поза некорректна — генерация прерывается на этапе API с выдачей понятной пользователю ошибки.
3.  **Социальные функции и каталог:**
    *   Каталог моделей с фильтрацией по категориям, форматам, поиском и сортировкой.
    *   Интерактивный 3D-просмотрщик моделей на базе React Three Fiber.
    *   Функции лайков, добавления в избранное и подписок на авторов.
    *   Рекурсивная древовидная система комментариев на фронтенде и бэкенде с возможностью ответов на любой комментарий.
4.  **Биллинг и монетизация:**
    *   Продажа пакетов кредитов и подписок Pro/Studio через интеграцию ЮKassa.
    *   Начисление кредитов происходит асинхронно через Webhook-обработчик платежей ЮKassa, защищенный от сбоев сети.
    *   Реализованы Cron-задачи (внутри lifespan FastAPI) для ежечасной проверки истечения подписок, автопродления через сохраненные платежные методы ЮKassa и ежемесячного сброса кредитных балансов.
5.  **Панель администратора (Admin Dashboard):**
    *   Визуализация динамики регистраций, генераций и доходов с помощью интерактивных графиков Recharts.
    *   Логирование административных действий.
    *   Управление жалобами (Reports) на модели или комментарии.
    *   Система предупреждений (Warnings): при выдаче 3-х предупреждений модератором, PostgreSQL триггер автоматически блокирует (банит) пользователя.

### В процессе реализации / Ограничения
*   **Генерация анимаций из видео:** Модуль `generate_animation_from_video` в `worker.py` временно содержит заглушку и возвращает ошибку `NotImplementedError`. Авто-риггинг Mixamo (`export_for_mixamo.py`) реализован как вспомогательный скрипт и требует финальной интеграции в сквозной пайплайн воркера.

## 5. КОМАНДЫ ЗАПУСКА И СБОРКИ

### Быстрый локальный запуск стека разработки (Windows)
Запустите PowerShell от имени администратора в корне проекта и выполните:
```powershell
Set-ExecutionPolicy Bypass -Scope Process
.\start-all.ps1
```
Скрипт автоматически запустит Redis, запустит FastAPI бэкенд, запустит фоновый ARQ-воркер и развернет Vite frontend в режиме разработки.

### Запуск по отдельности (Локальное окружение)

1.  **Запуск СУБД и Redis:**
    Убедитесь, что Docker запущен и локальный Redis работает (порт `6379`). Если Redis установлен в ОС:
    ```bash
    redis-server
    ```
2.  **Запуск Backend API:**
    ```bash
    cd animatic-ai/backend
    # Активируйте виртуальное окружение
    .\venv\Scripts\activate
    # Установка зависимостей (при первом запуске)
    pip install -r requirements.txt
    # Запуск сервера
    python main.py
    ```
    *API будет доступно по адресу:* `http://localhost:8000` (Swagger: `http://localhost:8000/docs`)

3.  **Запуск ARQ Worker (Очередь генерации):**
    Воркер должен запускаться в окружении с доступом к CUDA GPU:
    ```bash
    cd animatic-ai/backend
    .\venv\Scripts\activate
    python -m arq worker.WorkerSettings
    ```

4.  **Запуск Frontend (Режим разработки):**
    ```bash
    cd animatic-ai
    npm install
    npm run dev
    ```
    *Интерфейс будет доступен по адресу:* `http://localhost:5173`

---

### Сборка и запуск в Docker (Production)
Все конфигурации для докеризации находятся в директории `deploy/`. Перед запуском необходимо скопировать и настроить `.env` файл в директории `deploy/`.

Запуск мультиконтейнерного приложения:
```bash
cd deploy
docker-compose --env-file .env up -d --build
```
В данном режиме:
*   Frontend собирается в продакшн-бандл и отдается через Nginx на порту `80`.
*   API бэкенда крутится в CPU-only контейнере `backend` (порт `8000`), оптимизированном для легкой обработки роутов и модерации без CUDA.
*   GPU-воркер запускается отдельно на хост-машине (или выделенном GPU-сервере) и подключается к общей очереди Redis по сети.
*   Доступ из внешней сети наружу обеспечивается через Cloudflare Tunnel (`tunnel`).
